The Differentiator

Deterministic Delta + Constrained Synthesis

❌
Typical LLM Approach
•
LLM reads raw data and computes deltas itself
•
Model may hallucinate balances, dates, or amounts
•
No way to audit where a number came from
•
One bad inference poisons the whole brief
•
Token cost scales with data size and reasoning complexity
VS
✅
Our Approach
•
Java computes all deltas — zero LLM tokens
•
ChangeReport is the single ground-truth source
•
Claude writes prose ONLY from that report
•
Citation validator strips any unresolvable ID
•
One Sonnet call = predictable, minimal cost (~4¢)
The same architecture that eliminates hallucinations also minimises token cost — one decision, two wins.

Why It's Agentic

Tool-Calling Loop
In LLM-driven mode, Claude plans and sequences 6 tool calls itself. In eager mode, Java calls them deterministically for speed.
Observable Pipeline
Every phase emits named SSE events — the live agent-activity feed in the UI shows exactly what the agent is doing.
Validated Output
Claude's synthesis is checked against ground-truth IDs from the ChangeReport before the brief is returned — never blind trust.
Toggle in Config
app.agent.eager-tool-calls: true/false — switch between deterministic and full LLM orchestration without code changes.
